# AI Compatibility Register

This register records AI/runtime integration rules that are structural or
model/runtime-specific. It is not a list of phrase-specific behavior.

| ID | Location | Category | Reason and what breaks without it | Status / removal condition | Tests |
| --- | --- | --- | --- | --- | --- |
| AI-001 | `ai/prompts.py`, `ai/tool_router.py` | MODEL_COMPATIBILITY | `/no_think` suppresses visible Qwen reasoning. | Temporary for Qwen/llama.cpp; remove only after validating a replacement runtime. | multilingual prompt test |
| AI-002 | `scripts/start_local_llm.ps1` | MODEL_COMPATIBILITY | `--reasoning-format deepseek` is the proven llama.cpp Qwen response compatibility mode. | Temporary for the current llama.cpp/Qwen combination. | Local model diagnostics |
| AI-003 | `core/config.py`, `.env`, `ai/providers/llama_cpp.py` | STRUCTURAL | Explicit timeouts and output bounds prevent unbounded local inference waits and response growth. | Structural; revise only with measured runtime requirements. | provider error tests |
| AI-004 | `ai/tool_router.py` | STRUCTURAL | Candidate routing limits normal full-schema exposure while retaining allowlist validation. | Structural; revise only after capability and latency validation. | router coverage tests |
| AI-005 | `ai/providers/llama_cpp.py` | MODEL_COMPATIBILITY | Cosmetic JSON Schema fields are removed because llama.cpp does not need them and schemas cost CPU prefill. | Temporary for this provider adapter. | schema compaction test |
| AI-006 | `ai/providers/llama_cpp.py` | MODEL_COMPATIBILITY | Tool-result continuations omit repeated schemas and include the preceding assistant tool-call record, preventing context overflow and preserving protocol order. | Temporary for this runtime protocol. | continuation protocol test |
| AI-007 | `ai/tools/customer.py` | STRUCTURAL | `menu_get` exposes compact customer-safe model payloads rather than API-only detail. | Structural; expand only with a demonstrated response need. | AI tool and customer-menu tests |
| AI-008 | `ai/service.py`, `ai/grounded_response.py` | STRUCTURAL | Tool-backed turns require evidence and render executor results deterministically. Without this, model prose can bypass or contradict facts. | Structural; an evidence-bound verbalizer may supplement but not replace it. | grounded route and renderer tests |
| AI-009 | `scripts/start_local_llm.ps1`, `.env`, `scripts/start_local_llm.cmd` | STRUCTURAL | Model path and alias are configured through `.env`; the command launcher delegates to the configurable launcher. | Structural; no hard-coded model filename in launchers. | human launcher health checks |
| AI-010 | `ai/customer_intent.py` | STRUCTURAL | A typed customer intent plan separates model language interpretation from backend tool arguments and identifiers. Without it, a model must construct fragile production tool calls. | Structural; retain across model/runtime changes. | intent planner and service tests |
| AI-011 | `ai/intent_compiler.py` | STRUCTURAL | The compiler maps validated semantic plans to the existing allowlisted tools and resolves customer-visible entity names against authoritative data. Without it, internal IDs can be invented by a model. | Structural; retain across model/runtime changes. | compiler resolution tests |
| AI-012 | `ai/service.py`, `ai/tool_router.py` | TEMPORARY_WORKAROUND | The legacy candidate-router/direct-tool-call path is retained for injected provider compatibility and rollback only; production defaults to typed planning. | Remove after typed intent planning passes human typed, STT, and regression validation with no legacy consumer. | legacy conversation tests and typed service tests |
| AI-013 | `ai/customer_intent.py` | STRUCTURAL | Customer intent output is schema-constrained and Pydantic validated. Without it, semantic planning is less reliable. | Structural; retain for every provider. | intent planner tests and bounded local diagnostics |
| AI-014 | `ai/customer_intent.py` | STRUCTURAL | Raw model JSON is projected through the explicit CustomerIntentPlan field allowlist before semantic validation. Unknown and security-sensitive fields cannot reach compiler or executor. | Structural; never remove. | allowlist projection tests |
| AI-015 | `ai/providers/llama_cpp.py` | MODEL_COMPATIBILITY | llama.cpp accepts the compact plan schema through OpenAI-compatible `response_format: {type: json_object, schema: ...}`. | Replace only when a provider requires a different constrained-output request syntax. | bounded local diagnostics |
| AI-016 | `ai/customer_intent.py` | STRUCTURAL | Hierarchical planning classifies intent before extracting only that intent's slots. Without it, a universal schema makes unrelated fields compete. | Structural; retain across model and provider changes. | hierarchical planner tests |
| AI-017 | `ai/customer_intent.py` | STRUCTURAL | Intent-specific slot schemas expose only valid semantic fields for the classified capability. | Structural; retain across model and provider changes. | slot schema tests |
| AI-018 | `ai/intent_compiler.py` | STRUCTURAL | When a customer-visible dish name is uniquely present in the original utterance, authoritative normalization may resolve it after an unusable semantic reference. | Structural; retain while entity intents accept natural language. | entity fallback tests |
| AI-019 | `ai/customer_intent.py` | TEMPORARY_WORKAROUND | The broad single-plan planner remains available only for rollback and existing compatibility tests. | Remove after hierarchical planning passes human typed, STT, and regression validation. | legacy planner tests |
| AI-020 | `core/config.py`, `ai/providers/llama_cpp.py` | STRUCTURAL | The same OpenAI-compatible provider is configured by endpoint URL and model alias for local or remote inference. Restaurant services remain local. | Structural; retain across inference deployments. | remote provider tests |
| AI-021 | `core/config.py`, `ai/providers/llama_cpp.py` | STRUCTURAL | Optional bearer authentication is secret-backed and omitted when unset. | Structural; retain while authenticated endpoints are supported. | remote provider tests |
| AI-022 | `scripts/start_local_llm.ps1`, `scripts/start_human_typed_test.ps1` | MODEL_COMPATIBILITY | Local llama-server auto-start applies only in local runtime mode; remote mode must not require a GGUF or launch llama.cpp. | Remove only if local llama.cpp launch support is retired. | launcher guard tests |
